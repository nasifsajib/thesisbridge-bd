1. What is ThesisBridge BD?১. ThesisBridge BD কী?

ThesisBridge BD is a frontend web application — a "digital hub" for Bangladeshi university students. It solves one problem: students waste months searching for a thesis topic, a supervisor, and publication guidance, all scattered across different places. This platform puts the whole journey in one website: find an idea → find a supervisor → follow a roadmap → publish a paper.

It is a full-stack application: the interface is plain HTML, CSS and JavaScript, while the content, accounts and saved data are served by a Python (FastAPI) backend and a Supabase PostgreSQL database. Bookmarks, saved supervisors, roadmap progress, read guides, checklist ticks and connection requests are stored per user in the database.

বাংলা

ThesisBridge BD হলো একটি ফ্রন্টএন্ড ওয়েব অ্যাপ্লিকেশন — বাংলাদেশি বিশ্ববিদ্যালয়ের শিক্ষার্থীদের জন্য একটি "ডিজিটাল হাব"। সমস্যাটা হলো, শিক্ষার্থীরা থিসিসের আইডিয়া, সুপারভাইজার আর পাবলিকেশনের নিয়ম খুঁজতে মাসের পর মাস নষ্ট করে, কারণ জিনিসগুলো ভিন্ন ভিন্ন জায়গায় ছড়িয়ে-ছিটিয়ে থাকে। এই ওয়েবসাইটে পুরো যাত্রাটা এক জায়গায় আছে: আইডিয়া খোঁজা → সুপারভাইজার খোঁজা → রোডম্যাপ অনুসরণ করা → পেপার পাবলিশ করা।

এটি একটি ফুল-স্ট্যাক অ্যাপ্লিকেশন — ইন্টারফেস সাধারণ HTML, CSS ও JavaScript, আর কনটেন্ট, অ্যাকাউন্ট ও সেভ করা ডেটা আসে Python (FastAPI) ব্যাকএন্ড ও Supabase PostgreSQL ডেটাবেস থেকে। বুকমার্ক, সেভ করা সুপারভাইজার, রোডম্যাপ প্রোগ্রেস, পড়া গাইড, চেকলিস্ট ও কানেকশন রিকোয়েস্ট প্রতিটি ব্যবহারকারীর জন্য ডেটাবেসে জমা থাকে।

2. Technologies used২. যে টেকনোলজিগুলো ব্যবহার করা হয়েছে

  • HTML5 — the structure of the 6 pages.
  • CSS3 — all design: colors, layout (CSS Grid + Flexbox), animations, dark mode using CSS variables.
  • Vanilla JavaScript (ES5/ES6) — every interaction: search, filters, modals, quizzes, saving data. No React, no Vue, no jQuery.
  • Font Awesome — icons. Google Fonts — Sora, Inter, JetBrains Mono.
  • localStorage — browser storage used to remember user data (instead of a database).

Why no framework? A framework was not required, and vanilla JS proves the logic is understood at a deeper level — every feature is built by hand, so every line in the viva can be explained.

4. How the app works (the flow)৪. অ্যাপটি কীভাবে কাজ করে (পুরো ধারা)

Step 1: Browser opens the HTML page. Step 2: CSS applies the design. Step 3: JavaScript files run — each module finds its mount point using a data-mount attribute and renders content from data.js. Step 4: When the user clicks/filters/saves, JavaScript updates the page and writes state to localStorage. Step 5: On the next visit, saved state is read back — so bookmarks and progress survive refresh.

5. Sticky navigation + mobile drawer৫. স্টিকি নেভিগেশন ও মোবাইল মেনু

The navbar is sticky (always visible at the top) and responsive: on desktop all 6 links show; below 1080px the links move into a right-side drawer that opens with a hamburger button. Clicking a link closes the drawer, clicking the dark area (scrim) closes it, and every nav item actually navigates.

A real bug I fixed here: at first the mobile drawer appeared as a thin sliver. The reason: the navbar used backdrop-filter: blur(), and any element with a filter becomes the positioning reference for its position: fixed children — so the drawer's "fixed" coordinates were measured against the 72px navbar instead of the whole screen. Fix: move the blur to a ::before pseudo-element so the drawer stays fixed to the viewport.

বাংলা

নেভবারটি স্টিকি (সবসময় উপরে থাকে) এবং রেসপনসিভ: ডেস্কটপে ৬টি লিংক দেখা যায়, আর ১০৮০px-এর নিচে লিংকগুলো চলে যায় ডান পাশের ড্রয়ারে, যা হ্যামবার্গার বাটনে খোলে। লিংকে ক্লিক করলে মেনু বন্ধ হয়, বাইরের কালো আবরণে (scrim) ক্লিক করলেও বন্ধ হয়।

এখানে একটা আসল বাগ ঠিক করেছি: শুরুতে মোবাইল মেনুটা দেখা যাচ্ছিল শুধু একটা চিকন অংশ হয়ে। কারণটা ছিল — নেভবারে backdrop-filter: blur() ছিল, আর CSS-এর নিয়ম অনুযায়ী filter থাকা কোনো এলিমেন্ট তার position: fixed সন্তানের অবস্থান নির্ণয়ের রেফারেন্স হয়ে যায়। ফলে মেনুটা পুরো স্ক্রিনের বদলে ৭২px-এর নেভবারের সাপেক্ষে বসছিল। সমাধান: blur-টা ::before pseudo-element-এ সরিয়ে নিই।

/* Wrong: blur on .navbar breaks the fixed drawer inside it */
/* Right: blur on a pseudo-element, so children keep viewport-fixed */
.navbar::before {
  content: ''; position: absolute; inset: 0; z-index: -1;
  backdrop-filter: blur(14px);
}

FIX: bug → hamburger menu was invisible on mobile; cause → CSS containing-block rule; lesson → filters/transforms change how position: fixed works.

6. Hero section + interactive "Research Network"৬. হিরো অংশ ও ইন্টার‍্যাক্টিভ "রিসার্চ নেটওয়ার্ক"

The hero shows the headline "Your Bridge to Better Research." with two buttons that smooth-scroll to sections. On the right sits the highlight: a "FIG. 01 — The Research Network" card — 8 circular nodes (Idea, Gap, Method, Experiment, Supervisor, Thesis, Paper, Journal) connected by lines, drawn with SVG.

Three things make it alive: (a) small dots (pulses) travel along the edges, (b) nodes can be dragged with mouse or finger and spring back with physics, (c) tapping a node shows a guidance panel with a tip and a link — and the whole graph slides up so no node hides behind the panel.

বাংলা

হিরো অংশে আছে মূল শিরোনাম "Your Bridge to Better Research." আর দুটি বাটন, যেগুলো মসৃণভাবে নিচের সেকশনে স্ক্রল করে। ডান পাশে থাকে বিশেষ অংশটি: "FIG. 01 — The Research Network" কার্ড — ৮টি গোল নোড (Idea, Gap, Method, Experiment, Supervisor, Thesis, Paper, Journal) লাইন দিয়ে যুক্ত, SVG দিয়ে আঁকা।

এটাকে জীবন্ত করে তিনটি জিনিস: (ক) ছোট ছোট বিন্দু (pulse) লাইন ধরে চলাচল করে, (খ) নোডগুলো মাউস বা আঙুল দিয়ে টেনে সরানো যায়, ছেড়ে দিলে ফিজিক্স ব্যবহার করে নিজের জায়গায় ফিরে আসে, (গ) কোনো নোডে ট্যাপ করলে নিচে একটি প্যানেলে পরামর্শ ও লিংক দেখায় — আর পুরো গ্রাফ উপরে উঠে যায়, তাই কোনো নোড প্যানেলের আড়ালে লুকায় না।

// Spring physics: every frame, pull the node toward its anchor
n.vx = (n.vx + (anchor.x - n.x) * 0.016) * 0.90; // 0.016 pull, 0.90 damping
n.x += n.vx;

FIG: the whole "physics engine" is two lines — force toward target, then damping. Higher pull = snappier, higher damping = less bounce.

A real bug I fixed here: on mobile the graph collapsed to zero width. Cause: in a one-column CSS grid, margin: 0 auto on an item changes it from "stretch" to "shrink-to-fit" — and since the graph's children were absolutely positioned, its content width was 0. Fix: use width: 100%; justify-self: center; instead of auto margins.

Another fix: the guidance panel covered the bottom nodes. Fix: the panel's measured height becomes a bottomInset, and all node anchors re-compute within the remaining space — so the graph reflows above the panel.

বাংলা

এখানেও একটা বাগ ঠিক করেছি: মোবাইলে গ্রাফটা শূন্য প্রস্থে সংকুচিত হয়ে যাচ্ছিল। কারণ: এক-কলামের CSS grid-এ কোনো আইটেমে margin: 0 auto দিলে সেটা "stretch" থেকে "content অনুযায়ী ছোট" হয়ে যায় — আর গ্রাফের ভেতরের সব এলিমেন্ট absolute ছিল, তাই content-এর প্রস্থই ছিল শূন্য! সমাধান: auto margin-এর বদলে width: 100%; justify-self: center;।

আরেকটি ফিক্স: পরামর্শের প্যানেলটা নিচের নোডগুলোর উপর বসে যাচ্ছিল। সমাধান: প্যানেলের উচ্চতা মেপে সেটা bottomInset হিসেবে যোগ করা হয়, আর সব নোডের অবস্থান বাকি জায়গার ভেতরে নতুন করে হিসাব হয় — তাই গ্রাফ প্যানেলের উপরে সরে যায়।

7. Animated statistics counters৭. অ্যানিমেটেড পরিসংখ্যান

The home page shows 500+ Ideas, 100+ Topics, 50+ Areas, 1 Hub. function matchScore(sup, ans) {              // sup = supervisor, ans = answers
  let score = 0;
  if (sup.areas.includes(ans.area)) score += 45;              // 45% weight: area
  const hits = ans.techs.filter(t => sup.expertise.includes(t)).length;
  score += (hits / ans.techs.length) * 25;                    // 25% weight: tools
  if (sup.supervisionTypes.includes(ans.type)) score += 15;   // 15% weight: type
  score += 10;                                                // 10%: difficulty fit
  return Math.min(99, Math.round(score));                     // e.g. → "94% Match"
}

FIG: the matching algorithm — a weighted score out of 100. Weights were chosen by importance: the right research area matters most (45), tools next (25), then type (15), difficulty (10).

22. Likely viva questions (with short answers)২২. সম্ভাব্য ভাইভা প্রশ্ন ও উত্তর

Q: Why vanilla JavaScript instead of React?

A: The requirement was a framework-free prototype. It also demonstrates deeper understanding: every modal, filter and animation is hand-built, so I can explain any line. The architecture (data layer + state wrapper) keeps it backend-ready anyway.

প্রশ্ন: React-এর বদলে vanilla JavaScript কেন?

উত্তর: প্রোটোটাইপে ফ্রেমওয়ার্ক-মুক্ত থাকার শর্ত ছিল। এতে বোঝাও যায় যে বেসিক ব্যাপারগুলো ভালোভাবে আয়ত্তে আছে — প্রতিটি মডাল, ফিল্টার, অ্যানিমেশন হাতে লেখা, তাই যেকোনো লাইন ব্যাখ্যা করতে পারব। আর ডেটা লেয়ার + স্টেট র‍্যাপার থাকায় পরে ব্যাকএন্ডের সাথে যুক্ত করাও সহজ।

Q: Where is the data stored, since there is no database?

A: Content data (ideas, supervisors) is in js/data.js as JavaScript arrays. User data (bookmarks, progress, theme, profile) is in the browser's localStorage through a single TB.state wrapper — designed so it can be swapped for API calls.

প্রশ্ন: ডেটাবেস না থাকলে ডেটা কোথায় থাকে?

উত্তর: কনটেন্টের ডেটা (আইডিয়া, সুপারভাইজার) আছে js/data.js-এ JavaScript array হিসেবে। ইউজারের ডেটা (বুকমার্ক, প্রোগ্রেস, থিম, প্রোফাইল) থাকে ব্রাউজারের localStorage-এ, একটি TB.state র‍্যাপারের ভেতর দিয়ে — যা পরে API call দিয়ে বদলানোর জন্যই বানানো।

Q: How do the combined filters work?

A: AND logic. The list is passed through Array.filter() and a card survives only if it passes every active condition — search text, category, difficulty, type and technology (section 8 shows the code).

প্রশ্ন: একাধিক ফিল্টার একসাথে কীভাবে কাজ করে?

উত্তর: AND লজিকে। তালিকাটা Array.filter()-এর ভেতর দিয়ে যায়, আর কোনো কার্ড থাকবে শুধু তখনই যখন সব চালু শর্তে পাস করে — সার্চ টেক্সট, ক্যাটাগরি, ডিফিকাল্টি, টাইপ ও টেকনোলজি (সেকশন ৮-এ কোড আছে)।

Q: Is the supervisor matching real AI?

A: No — and the UI says so. It is a transparent weighted scoring function (area 45%, tools 25%, type 15%, difficulty 10%). A real version would rank supervisors from verified publication data on a server.

প্রশ্ন: সুপারভাইজার ম্যাচিং কি আসল AI?

উত্তর: না — আর ইন্টারফেসে তাই লেখাও আছে। এটি একটি স্পষ্ট ওয়েটেড স্কোরিং ফাংশন (এরিয়া ৪৫%, টুলস ২৫%, টাইপ ১৫%, ডিফিকাল্টি ১০%)। আসল সংস্করণে সার্ভারে যাচাই করা পাবলিকেশন ডেটা থেকে র‍্যাংক করা হবে।

Q: What was the hardest bug?

A: The mobile drawer that rendered as a sliver. backdrop-filter on the navbar made it the containing block for the position: fixed drawer, so the drawer's coordinates were relative to a 72px bar. Fixed by moving the blur to a pseudo-element. It taught me that filters/transforms change how fixed positioning works.

প্রশ্ন: সবচেয়ে কঠিন বাগ কোনটা ছিল?

উত্তর: মোবাইলে মেনুটা চিকন অংশ হয়ে দেখাচ্ছিল। নেভবারের backdrop-filter তাকে position: fixed ড্রয়ারের containing block বানিয়ে ফেলেছিল, তাই ড্রয়ারের স্থানাঙ্ক পুরো স্ক্রিনের বদলে ৭২px বারের সাপেক্ষে হিসাব হচ্ছিল। blur-টা pseudo-element-এ সরিয়ে ঠিক করেছি। শিক্ষা: filter/transform থাকলে fixed positioning-এর আচরণ বদলে যায়।

Q: How did you test responsiveness?

A: In a real browser at 320/375/768/1024/1440 px: opened every page, exercised every interactive element (menus, modals, quiz, forms), took screenshots, and programmatically measured scrollWidth vs viewport width on all 6 pages to prove there is no horizontal overflow.

প্রশ্ন: রেসপনসিভনেস কীভাবে টেস্ট করেছ?

উত্তর: আসল ব্রাউজারে ৩২০/৩৭৫/৭৬৮/১০২৪/১৪৪০ px-এ: প্রতিটি পেজ খুলেছি, সব ইন্টার‍্যাক্টিভ জিনিস (মেনু, মডাল, কুইজ, ফর্ম) চালিয়েছি, স্ক্রিনশট নিয়েছি, এবং ৬টি পেজেই scrollWidth বনাম viewport width মেপে প্রমাণ করেছি পাশে কোনো স্ক্রল নেই।

Q: How would you connect a real backend?

A: The system has exactly two data doors: data.js (content) and TB.state (user data). A backend version replaces those two with API calls — the UI modules never touch storage directly, so nothing else changes. That was an explicit design decision from day one.

প্রশ্ন: আসল ব্যাকএন্ড যুক্ত করবে কীভাবে?

উত্তর: পুরো সিস্টেমে ডেটার ঠিক দুটি দরজা: data.js (কনটেন্ট) আর TB.state (ইউজার ডেটা)। ব্যাকএন্ড সংস্করণে এই দুটোকে API call দিয়ে বদলালেই হবে — UI মডিউলগুলো সরাসরি storage ধরে না, তাই অন্য কিছু বদলাতে হবে না। এটা প্রথম দিন থেকেই ইচ্ছাকৃত ডিজাইন সিদ্ধান্ত ছিল।

A. Turning data into cards — research.js → renderGrid()ক. ডেটা থেকে কার্ড বানানো — research.js

  return '<article class="idea-card">' +             // ② build an HTML string

B. One listener for all cards — event delegationখ. সব কার্ডের জন্য একটাই লিসেনার — event delegation

mount.addEventListener('click', function (e) {       // listen on the CONTAINER
  const view = e.target.closest('[data-action="view-idea"]');
  if (view) TB.openIdeaModal(parseInt(view.dataset.id, 10));
});
  • e.target — the exact element that was clicked (maybe the icon inside the button, not the button itself).

  • Because the listener sits on the container, it keeps working after cards are re-rendered (every filter/search re-render) — no re-binding needed. This pattern is called event delegation.

  • লিসেনারটা কন্টেইনারে বসানো, তাই কার্ড বারবার নতুন করে বসালেও (ফিল্টার/সার্চে) লিসেনার মরে না — আবার বাঁধতে হয় না। এই কৌশলের নাম event delegation।

C. Debounce — why the search never lagsগ. Debounce — সার্চ কেন ধীর হয় না

searchInput.addEventListener('input', TB.debounce(function () {
  renderGrid();
}, 140));

// the helper (main.js)
TB.debounce = function (fn, ms) {
  let timer;
  return function () {
    clearTimeout(timer);          // ① cancel the previous wait
    timer = setTimeout(fn, ms);   // ② start a fresh wait
  };
};
  • input fires on every keystroke — re-rendering the whole grid per letter is wasteful.
  • debounce returns a wrapped function that only runs the real work after 140 ms of silence.
  • Each new keystroke resets the timer (① cancels, ② restarts) — so filtering runs once, right after you stop typing.
বাংলা
  • input ইভেন্ট প্রতিটা অক্ষরে চলে — প্রতি অক্ষরে পুরো গ্রিড আঁকা অপচয়।
  • debounce এমন একটা মোড়ানো ফাংশন দেয় যা কাজটা করে শুধু ১৪০ মিলিসেকেন্ড চুপ থাকার পর।
  • প্রতিটা নতুন অক্ষর টাইমার রিসেট করে (① বাতিল, ② নতুন করে শুরু) — ফলে টাইপ থামার পর একবারই রেন্ডার হয়।

D. TB.state — the storage door (line by line)ঘ. TB.state — স্টোরেজের দরজা (লাইন ধরে)

TB.state = {
  get: function (key, def) {
    try {
      const raw = localStorage.getItem(key);    // ① read the TEXT (or null)
      if (raw !== null) return JSON.parse(raw); // ② text → real value
    } catch (e) { /* corrupted value → ignore */ }
    return def;                                 // ③ nothing saved → default
  },
  set: function (key, val) {
    localStorage.setItem(key, JSON.stringify(val));            // value → text
    document.dispatchEvent(new CustomEvent('tb:change', { detail: { key: key } }));
  }                                            // ④ announce "data changed!"
};
  • Why JSON at all? localStorage can only store text. JSON.stringify turns arrays/objects into text; JSON.parse turns them back.
  • get never returns undefined — if nothing is saved it returns the default, so callers are always safe. try/catch guards against corrupted saved text.
  • ④ is the clever part: after saving, a tb:change event is broadcast. Other modules listen for it — e.g. the bookmark badge on the navbar updates instantly on every page, because everyone hears the same announcement.
বাংলা
  • JSON কেন দরকার? localStorage শুধু লেখা (টেক্সট) রাখতে পারে। JSON.stringify array/object-কে টেক্সট বানায়, JSON.parse আবার আগের রূপে ফেরায়।
  • get কখনো undefined দেয় না — কিছু সেভ না থাকলে def (ডিফল্ট) দেয়, তাই ডাকা জায়গাগুলো নিরাপদ। try/catch নষ্ট ডেটার বিরুদ্ধে ঢাল।
  • ④ নম্বরটাই চালাকি: সেভ করার পর একটা tb:change ঘোষণা ছড়িয়ে দেওয়া হয়। অন্য মডিউলগুলো এই ঘোষণা শুনে নিজেদের আপডেট করে — যেমন নেভবারের বুকমার্ক ব্যাজ সব পেজে সঙ্গে সঙ্গে বদলে যায়, কারণ সবাই একই ঘোষণা শোনে।

const stack = [];                          // every open dialog, in order

F. Counter animation — the easing mathচ. কাউন্টার অ্যানিমেশন — easing-এর অংক

const tick = function (now) {
  const p = Math.min((now - start) / 1500, 1);   // ① progress: 0 → 1 in 1.5s
  const eased = 1 - Math.pow(1 - p, 3);          // ② ease-out curve
  el.textContent = Math.round(target * eased) + suffix;
  if (p < 1) requestAnimationFrame(tick);        // ③ next screen frame
};
  • ① p = how far through the animation we are (0 at start, 1 at end); Math.min(…, 1) caps it so it never overshoots.
  • ② the curve 1-(1-p)³ makes counting fast at first, slow at the end. Check: p = 0.5 → eased ≈ 0.875 — already 87% there.
  • ③ requestAnimationFrame(tick) says "call me again before the next screen frame" (~60×/second) — the browser's built-in animation clock.
বাংলা
  • ① p = অ্যানিমেশন কতদূর এগোলো (শুরুতে ০, শেষে ১); Math.min(…, 1) সীমা টানে, যাতে ১-এর বেশি না হয়।
  • ② সূত্রটা 1-(1-p)³ — শুরুতে দ্রুত গুনে, শেষে ধীরে থামে। হিসাব দেখো: p = 0.5 হলে eased ≈ 0.875 — অর্থাৎ অর্ধেক সময়েই ৮৭% পথ পাড়ি।
  • ③ requestAnimationFrame(tick) বলে "পরের স্ক্রিন-ফ্রেমের আগে আমাকে আবার ডাকো" (সেকেন্ডে ~৬০ বার) — এটাই ব্রাউজারের নিজস্ব অ্যানিমেশন ঘড়ি।

G. Match score — the weighted formula, line by lineছ. ম্যাচ স্কোর — ওয়েটেড সূত্র, লাইন ধরে

function matchScore(sup, ans) {
  let score = 0;                                            // ① start at 0
  if (sup.areas.includes(ans.area)) score += 45;            // ② right area?
  const hits = ans.techs.filter(t => sup.expertise.includes(t)).length;
  score += (hits / ans.techs.length) * 25;                  // ③ tool overlap
  if (sup.supervisionTypes.includes(ans.type)) score += 15; // ④ right type?
  score += 10;                                              // ⑤ difficulty fit
  return Math.min(99, Math.round(score));                   // ⑥ clamp + round
}
  • ② 45 points for the research area — the single most important thing, hence the biggest weight.
  • ③ hits = how many of the user's technologies the supervisor actually knows; the fraction is scaled to 25. Knowing all tools = 25, half = 12.5.
  • ④⑤ supervision type (15) and a flat difficulty fit (10) complete the 100-point scale.
  • ⑥ Math.min(99, …) — never display a fake 100%; round to a whole number.
বাংলা
  • ② ৪৫ পয়েন্ট রিসার্চ এরিয়া মিললে — সবচেয়ে গুরুত্বপূর্ণ বিষয়, তাই সবচেয়ে বড় ওয়েট।
  • ③ hits = ইউজারের জানা টেকনোলজির মধ্যে সুপারভাইজার আসলে ক'টা জানেন; ভগ্নাংশটা ২৫-এ স্কেল করা। সবগুলো জানলে ২৫, অর্ধেক জানলে ১২.৫।
  • ④⑤ সুপারভিশন টাইপ (১৫) আর ডিফিকাল্টি-ফিট (১০) — মিলিয়ে ১০০-এর স্কেল পূর্ণ।
  • ⑥ Math.min(99, …) — কখনো মিথ্যা ১০০% দেখায় না; পূর্ণসংখ্যায় ঘোরানো হয়।

H. Spring physics — a two-line engineজ. স্প্রিং ফিজিক্স — দুই লাইনের ইঞ্জিন

n.vx = (n.vx + (anchor.x - n.x) * 0.016) * 0.90;   // ① velocity update
n.x  = n.x + n.vx;                                 // ② move the node
  • (anchor.x - n.x) — the distance from home. Multiplied by 0.016 it becomes a gentle pull toward home (the spring force).
  • That force is added to the existing velocity — so the node keeps momentum (inertia), it doesn't teleport.
  • × 0.90 — damping: every frame 10% of the velocity disappears, so the wobble eventually settles instead of bouncing forever.
  • ② applies the velocity. Pull + inertia + friction = a real spring feel, in two lines. (Same pattern on the y-axis.)
বাংলা
  • (anchor.x - n.x) — বাড়ি থেকে দূরত্ব। ×০.০১৬ করলে সেটা হয় বাড়ির দিকে হালকা টান (স্প্রিং-বল)।
  • টানটা আগের বেগের সাথে যোগ হয় — তাই নোডটা ঝাঁপ দেয় না, ভেসে ভেসে আসে (জড়তা/inertia)।
  • × ০.৯০ — ড্যাম্পিং: প্রতি ফ্রেমে বেগের ১০% কমে যায়, তাই দুলতে দুলতে একসময় থেমে যায়, চিরকাল দোলে না।
  • ② বেগ ধরে নোড সরায়। টান + জড়তা + ঘর্ষণ = আসল স্প্রিং-এর অনুভূতি, মাত্র দুই লাইনে। (y-অক্ষেও একই প্যাটার্ন।)

I. Dark mode — why one attribute re-colors everythingঝ. ডার্ক মোড — একটা attribute-এ সব রং কেন বদলায়

:root               { --bg: #f5f8f6; }      /* the default values */
[data-theme='dark'] { --bg: #0c1512; }      /* same names, dark values */

.card  { background: var(--bg); }           /* 200+ rules all read --bg */
  • var(--bg) is not a stored color — it is a live lookup that re-resolves whenever the variable changes.
  • Toggling data-theme on <html> makes the browser re-compute every rule that uses any variable — the whole site repaints at once.
  • That is why no component needs a separate "dark version" — components only consume variables; the theme owns the values.
বাংলা
  • var(--bg) কোনো জমানো রং নয় — এটা সরাসরি চলমান খোঁজ, variable বদলালেই নতুন মান নিয়ে নেয়।
  • <html>-এ data-theme বদলালেই ব্রাউজার যেসব নিয়মে variable ব্যবহার হয়েছে সবগুলো নতুন করে হিসাব করে — গোটা সাইট এক নিমেষে রঙ বদলায়।
  • তাই কোনো কম্পোনেন্টের আলাদা "ডার্ক সংস্করণ" লাগে না — কম্পোনেন্ট শুধু variable ব্যবহার করে; মানগুলোর মালিক থিম।
