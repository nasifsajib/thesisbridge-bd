1What we builtকী বানিয়েছি

ThesisBridge BD began as six static HTML pages. Every research idea, supervisor and FAQ lived inside public/js/data.js, and anything the visitor saved (bookmarks, roadmap ticks, checklist ticks) went into the browser's localStorage. That had three consequences: the data was invisible to a teacher reading the source, it disappeared when the browser storage was cleared, and two students could not share anything.

ThesisBridge BD শুরু হয়েছিল ছয়টি স্ট্যাটিক HTML পেজ দিয়ে। প্রতিটি গবেষণা আইডিয়া, সুপারভাইজার ও FAQ থাকত public/js/data.js-এর ভিতরে, আর ইউজার যা সেভ করত (বুকমার্ক, রোডম্যাপ টিক, চেকলিস্ট টিক) তা যেত ব্রাউজারের localStorage-এ। এতে তিনটি সমস্যা ছিল: ডেটা সোর্স পড়ে দেখা যেত না, ব্রাউজার স্টোরেজ মুছলে সব হারিয়ে যেত, আর দুইজন শিক্ষার্থী একে অন্যের কিছু দেখতে পারত না।

2Architectureআর্কিটেকচার

The important design choice: the API is a separate application. Vercel hosts two things side by side — the static pages from public/ and the Python function from app/main.py — so the browser talks to the same domain and no CORS problem exists in production.

সবচেয়ে গুরুত্বপূর্ণ সিদ্ধান্ত: API আলাদা একটি অ্যাপ্লিকেশন। Vercel একসাথে দুটি জিনিস হোস্ট করে — public/ থেকে স্ট্যাটিক পেজ আর app/main.py থেকে Python ফাংশন — তাই ব্রাউজার একই ডোমেইনে কথা বলে, প্রোডাকশনে CORS সমস্যা থাকে না।

One request, step by stepএকটি রিকোয়েস্ট, ধাপে ধাপে

  1. The student clicks Bookmark. research.js updates the JavaScript array and writes it to localStorage immediately, so the button answers instantly.শিক্ষার্থী Bookmark চাপে। research.js সাথে সাথে JavaScript অ্যারে আপডেট করে localStorage-এ লেখে, তাই বোতামটি তৎক্ষণাৎ সাড়া দেয়।
  2. api.js then calls PUT /api/me/bookmarks/ideas with the whole list and the token from localStorage.এরপর api.js পুরো লিস্ট আর localStorage-এর টোকেন নিয়ে PUT /api/me/bookmarks/ideas কল করে।
  3. Vercel runs api/index.py, which imports the app from app/main.py. FastAPI matches the path, validates the JSON with a Pydantic model, and rejects bad input with 422 before any code runs.Vercel api/index.py চালায়, যা app/main.py থেকে অ্যাপ আমদানি করে। FastAPI পাথ মিলিয়ে, Pydantic মডেল দিয়ে JSON যাচাই করে, আর ভুল ইনপুটে কোড চলার আগেই 422 ফেরত দেয়।
  4. dependencies.py reads the Authorization header and asks Supabase Auth who the token belongs to. Invalid token → 401, and the route never runs.dependencies.py Authorization হেডার পড়ে Supabase Auth-কে জিজ্ঞেস করে টোকেনটি কার। টোকেন ভুল হলে → 401, রুটটি আর চলে না।
  5. The router upserts the requested ids, then deletes rows that are no longer in the list — so the table ends up exactly matching the browser array.রাউটার চাওয়া id-গুলো upsert করে, তারপর লিস্টে নেই এমন রো ডিলিট করে — ফলে টেবিল হুবহু ব্রাউজার অ্যারের মতো হয়।
  6. A JSON answer returns to the browser. If it fails, api.js logs one warning and the screen keeps working from the local cache.JSON উত্তর ব্রাউজারে ফেরে। ব্যর্থ হলে api.js একটি ওয়ার্নিং লগ করে আর স্ক্রিন লোকাল ক্যাশ থেকেই কাজ চালিয়ে যায়।

class ConfigurationError(RuntimeError):
    """
    Raised when required environment variables are missing.

    main.py turns this into a clean HTTP 503 answer instead of a traceback.
    """


def missing_settings() -> list[str]:
    """
    Return the names of environment variables that are still empty.

    The function is used by /api/health (to report a setup problem politely)
    and by database.py (to stop with a clear error message instead of a
    confusing Supabase stack trace).
    """
    missing = []

    if not SUPABASE_URL:
        missing.append("SUPABASE_URL")
    if not SUPABASE_ANON_KEY:
        missing.append("SUPABASE_ANON_KEY")
    if not SUPABASE_SERVICE_ROLE_KEY:
        missing.append("SUPABASE_SERVICE_ROLE_KEY")

    return missing


def ensure_settings() -> None:
    """
    Raise a RuntimeError that a human can understand if keys are missing.

    Called before the first Supabase client is created.

    missing = missing_settings()

            "Missing environment variables: "
            + ", ".join(missing)
            + ". Copy `.env.example` to `.env` and fill in your Supabase keys, "
            "or add them in the Vercel project settings."
        )

Row Level Security (RLS)Row Level Security (RLS)

RLS is a PostgreSQL feature: even if someone obtained the publishable key and called Supabase directly, the database itself refuses to return another student's rows. Our API uses the secret key, which bypasses RLS — so the policies protect the direct path, and the Python code protects the API path.

RLS হলো PostgreSQL-এর একটি বৈশিষ্ট্য: কেউ publishable কী নিয়ে সরাসরি Supabase-কে কল করলেও ডেটাবেস নিজেই অন্য শিক্ষার্থীর রো ফেরত দিতে অস্বীকার করে। আমাদের API সিক্রেট কী ব্যবহার করে, যা RLS বাইপাস করে — তাই পলিসিগুলো সরাসরি পথ রক্ষা করে, আর Python কোড API পথ রক্ষা করে।

) -> JSONResponse:

    The most common one on a fresh project is PGRST205: the table does not

        status_code=503,
        content={"detail": detail},

"""
app/database.py
---------------
Creates and reuses the two Supabase clients the backend needs.

WHY TWO CLIENTS?

1. `get_auth_client()` uses the ANON key.
   Supabase Auth endpoints (sign up, sign in, verify a token) are designed to
   be called with the anon key. Using the service role key for those calls
   would give the account more power than it should have.

2. `get_admin_client()` uses the SERVICE ROLE key.
   Table queries and profile inserts need permission to bypass Row Level
   Security, so they use the service role key. This key stays on the server.

Creating a new client on every request would be slow, so each client is
created once and then reused (a simple lazy singleton).
"""

from supabase import Client, create_client

from app.config import (
    SUPABASE_ANON_KEY,
    SUPABASE_SERVICE_ROLE_KEY,
    SUPABASE_URL,
    ensure_settings,

_auth_client: Client | None = None
_admin_client: Client | None = None


def get_auth_client() -> Client:
    """
    Return the client used for Supabase Auth operations.

    It uses the public anon key, which is the normal key for auth calls.
    """
    global _auth_client

    if _auth_client is None:
        ensure_settings()
        _auth_client = create_client(SUPABASE_URL, SUPABASE_ANON_KEY)

    return _auth_client

    It uses the service role key, so it can bypass Row Level Security.
    Never expose this client (or its key) to the frontend.

    global _admin_client

"""
app/dependencies.py
-------------------
Reusable FastAPI dependencies.

A "dependency" is a function FastAPI calls automatically before your route,
so the route does not need to repeat boring work such as:

  - reading the "Authorization: Bearer <token>" header,
  - asking Supabase whether the token is valid,
  - returning HTTP 401 when it is not.

Supabase Auth signs the token, and `auth.get_user(token)` verifies it with
Supabase. That means we do not have to write our own JWT secret management.
"""

from fastapi import Header, HTTPException, status

from app.config import ConfigurationError
from app.database import get_auth_client


def _extract_token(authorization: str | None) -> str | None:
    """
    Pull the token out of a header that looks like:

        Authorization: Bearer eyJhbGciOi...

    Returns None when the header is missing or has the wrong shape.
    """
    if not authorization:
        return None

    parts = authorization.split(" ", 1)

    if len(parts) != 2 or parts[0].lower() != "bearer":
        return None

    token = parts[1].strip()
    return token or None


def get_current_user(authorization: str | None = Header(default=None)) -> dict:
    """
    FastAPI dependency for routes that REQUIRE a logged-in user.

    Usage inside a router:

        @router.get("/me/state")
        def read_state(user: dict = Depends(get_current_user)):
            ...

    Returns a small dictionary: {"id": "...", "email": "...", "token": "..."}.
    """
    token = _extract_token(authorization)

    if token is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Please log in to continue.",
            headers={"WWW-Authenticate": "Bearer"},
        )

    try:
        # Supabase checks the signature and expiry, then returns the user.
        response = get_auth_client().auth.get_user(token)
        supabase_user = response.user
    except ConfigurationError:
        # The .env file is missing: let main.py answer with a clear HTTP 503.
        raise
    except Exception:
        # Bad signature, expired token, deleted account, network problem...
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Your session has expired. Please log in again.",
            headers={"WWW-Authenticate": "Bearer"},
        )

    if supabase_user is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Your session has expired. Please log in again.",
            headers={"WWW-Authenticate": "Bearer"},
        )

    return {
        "id": supabase_user.id,
        "email": supabase_user.email,
        "token": token,
    }


def get_optional_user(authorization: str | None = Header(default=None)) -> dict | None:
    """
    FastAPI dependency for public routes that ALSO want to know the user when
    one is logged in.

    Example: sending a connection request works for guests and members, but
    when a member sends it we attach their user id.

    A broken token is treated as "guest" instead of an error, because the
    route itself is public.
    """
    token = _extract_token(authorization)

    if token is None:
        return None

    try:
        response = get_auth_client().auth.get_user(token)
        supabase_user = response.user
    except Exception:
        return None

    if supabase_user is None:
        return None

    return {
        "id": supabase_user.id,
        "email": supabase_user.email,
        "token": token,
    }

app/schemas.py
--------------
Pydantic models = the "shape" of every request and response.

Two jobs:

1. VALIDATION - FastAPI checks incoming JSON against these models and returns
   a clear HTTP 422 error when a field is missing or invalid.

2. SERIALIZATION - FastAPI converts the data we return into JSON. The frontend

   their own naming style.

def _fetch(table: str, *, order: str | None = None) -> list[dict]:
    """
    Read every row of a table with the service-role client.

    `order` is the column name used for sorting, e.g. "position" or "id".
    """
    db = get_admin_client()
    query = db.table(table).select("*")

    if order is not None:
        query = query.order(order)

    response = query.execute()
    return response.data or []


def _safe_search(text: str) -> str:
    """
    Make user text safe to insert into a PostgREST filter.

    PostgREST uses commas and parentheses as filter syntax, so a search for
    "AI, ML (2024)" would break the query. Replacing those characters with
    spaces keeps the search working and cannot inject extra filters.
    """
    return re.sub(r"[,()*]", " ", text).strip()


def _single(table: str, row_id: int | str, id_column: str = "id") -> dict:
    """
    Return one row or raise a clean 404.

    We use limit(1) instead of maybe_single() because the behaviour is the
    same across every supabase-py version: the data is always a list.
    """
    db = get_admin_client()
    response = (
        db.table(table)
        .select("*")
        .eq(id_column, row_id)
        .limit(1)
        .execute()
    )
    rows = response.data or []

    if not rows:
        raise HTTPException(status_code=404, detail=f"No record found in {table}.")

    return rows[0]

@router.get(
    "/ideas",
    response_model=IdeaListResponse,
    summary="Search and filter research ideas",
)
def list_ideas(
    q: str | None = Query(default=None, description="Text search"),
    category: str | None = Query(default=None),
    difficulty: str | None = Query(default=None),
    type: str | None = Query(default=None),
    technology: str | None = Query(default=None),
    sort: str = Query(default="recommended"),
    limit: int = Query(default=20, ge=1, le=100),
    offset: int = Query(default=0, ge=0),
) -> IdeaListResponse:
    """
    Every filter is optional and they combine with AND, exactly like the
    frontend explorer.
    """
    db = get_admin_client()

    # count="exact" asks PostgreSQL for the total number of matching rows, so
    # the response can say "Showing 20 of 20 ideas".
    query = db.table("research_ideas").select("*", count="exact")

    # --- text search -------------------------------------------------------
    if q:
        search = _safe_search(q)
        if search:
            # or_() means: match ANY of these columns.
            query = query.or_(
                f"title.ilike.%{search}%,"
                f"description.ilike.%{search}%,"
                f"category.ilike.%{search}%,"
                f"area.ilike.%{search}%"
            )

    # --- exact filters -----------------------------------------------------
    if category:
        query = query.eq("category", category)
    if difficulty:
        query = query.eq("difficulty", difficulty)
    if type:
        query = query.eq("type", type)

    # --- array filter ------------------------------------------------------
    # technologies is a text[] column; contains() checks one element.
    if technology:
        query = query.contains("technologies", [technology])

    # --- sorting -----------------------------------------------------------
    column, descending = IDEA_SORTS.get(sort, IDEA_SORTS["recommended"])
    query = query.order(column, desc=descending)

    # --- pagination --------------------------------------------------------
    # range() is inclusive on both ends.
    query = query.range(offset, offset + limit - 1)

    response = query.execute()
    rows = response.data or []

    return IdeaListResponse(
        total=response.count if response.count is not None else len(rows),
        items=[ResearchIdea.model_validate(row) for row in rows],
    )

            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Could not create the account. Please check the email and "
            "password, then try again.",
        )

    auth_user = getattr(created, "user", None)

    if auth_user is None:
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail="Supabase did not return the new user.",
        )

    # ---- Step 2: create the public profile row ---------------------------
    profile_row = {
        "id": auth_user.id,
        "name": payload.name.strip(),
        "email": email,
        "university": _clean(payload.university),
        "department": _clean(payload.department),
        "student_id": _clean(payload.student_id),
        "interest": _clean(payload.interest),
    }

    try:
        admin.table("profiles").insert(profile_row).execute()
    except Exception:
        # Roll back step 1 so we never leave an auth user with no profile.
        try:
            admin.auth.admin.delete_user(auth_user.id)
        except Exception:
            pass

        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail="The profile could not be saved, so the account was not created.",
        )

    try:
        session_result = get_auth_client().auth.sign_in_with_password(
            {"email": email, "password": payload.password}
        )
    except Exception:
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail="Account created, but automatic login failed. Please log in.",
        )

    profile = _profile_for(auth_user.id) or profile_row

        access_token=_token_from_session(session_result),
        user=UserOut.model_validate(profile),

def _replace_rows(
    db,
    table: str,
    user_id: str,
    id_column: str,
    ids: list,
) -> None:
    """
    Make the table contain exactly `ids` for this user.

    Order matters:
      1. UPSERT the requested rows first (creates missing ones, keeps existing).
      2. DELETE the rows that are not in the new list.

    If step 1 fails (for example an id that does not exist), nothing has been
    deleted yet, so the user's old data is still safe.
    """
    if ids:
        rows = [{"user_id": user_id, id_column: value} for value in ids]
        try:
            db.table(table).upsert(
                rows,
                on_conflict=f"user_id,{id_column}",
            ).execute()
        except Exception:
            raise HTTPException(
                status_code=status.HTTP_400_BAD_REQUEST,
                detail=f"One or more values sent for {table} do not exist.",
            )

    delete_query = db.table(table).delete().eq("user_id", user_id)

    if ids:
        # Keep the rows we just upserted; delete every other row.
        delete_query = delete_query.not_.in_(id_column, ids)

    delete_query.execute()

def upsert_rows(client, table: str, rows: list[dict], conflict: str) -> None:
    """
    Send `rows` to one table in batches.

    `conflict` is the column (or comma-separated columns) that identifies a
    row, e.g. "id" or "kind,value". Supabase updates the row when it exists
    and inserts it when it does not.
    """
    if not rows:
        print(f"  {table}: nothing to insert")
        return

    for start in range(0, len(rows), BATCH_SIZE):
        batch = rows[start : start + BATCH_SIZE]
        client.table(table).upsert(batch, on_conflict=conflict).execute()

    print(f"  {table}: {len(rows)} rows")


def count_rows(client, table: str) -> int:
    """
    Ask PostgreSQL for COUNT(*) without downloading the rows.

    limit(1) keeps the response small; count="exact" is what returns the total.
    """
    response = (
        client.table(table).select("*", count="exact").limit(1).execute()
    )
    return response.count or 0

Why the whole list, not one item at a time?কেন পুরো লিস্ট, একবারে একটি নয়?

Adding and removing an item is two different API calls (POST and DELETE), and they can arrive out of order. Sending the whole array makes the operation idempotent: sending [1,2] twice leaves exactly the same two rows, and the browser array and the table can never drift apart.

/* ==========================================================================
   ThesisBridge BD - API connection layer (js/api.js)
   --------------------------------------------------------------------------
   This file is the bridge between the existing HTML/CSS/JS interface and the
   new Python backend.

   What it does, in order:

     1. Finds the backend URL (localhost:8000 in development, same domain
        on Vercel).
     2. Loads the public content from GET /api/content and puts it into
        window.TB_DATA. If the backend is offline, it keeps the bundled
        js/data.js copy so the site still works.
     3. Replaces TB.state.get/set so that saved ideas, saved supervisors,
        roadmap progress, read guides and checklist ticks are stored in
        Supabase for logged-in users. Guests keep the old localStorage
        behaviour.
     4. Exposes TB.auth.login / signup / logout and TB.ready.

   Load order in every HTML page:
        js/data.js  ->  js/main.js  ->  js/api.js  ->  feature modules
   Feature modules wait for TB.ready before they render, so they always read
   the data that came from the database.
   ========================================================================== */

window.TB = window.TB || {};

(function (TB) {
  'use strict';

  /* ------------------------------------------------------------------
     1. WHERE IS THE BACKEND?
     ------------------------------------------------------------------ */

  var API_BASE = (function () {
    // A page may override the URL by setting window.TB_API_BASE before this
    // file loads (useful when the API is deployed somewhere else).
    if (typeof window.TB_API_BASE === 'string' && window.TB_API_BASE) {
      return window.TB_API_BASE.replace(/\/+$/, '');
    }

    // Opened directly from disk (file://) -> the local uvicorn server.
    if (window.location.protocol === 'file:') {
      return 'http://127.0.0.1:8000';
    }

    // Local development: HTML on port 8417, FastAPI on port 8000.
    if (window.location.hostname === 'localhost' ||
        window.location.hostname === '127.0.0.1') {
      return 'http://127.0.0.1:8000';
    }

    // Production (Vercel): the API is on the same domain, so a relative URL
    // is enough. "" + "/api/content" becomes "/api/content".
    return '';
  })();

  TB.API_BASE = API_BASE;

  /* ------------------------------------------------------------------
     2. SESSION TOKEN STORAGE
     ------------------------------------------------------------------
     Supabase returns an access token after login. We keep it in
     localStorage and send it as "Authorization: Bearer <token>".
     The token is NOT a password: it expires (one hour by default) and can
     be revoked by Supabase.
     ------------------------------------------------------------------ */

  var TOKEN_KEY = 'tb_token';

  function readToken() {
    try {
      return localStorage.getItem(TOKEN_KEY) || null;
    } catch (error) {
      return null;
    }
  }

  function writeToken(token) {
    try {
      localStorage.setItem(TOKEN_KEY, token);
    } catch (error) {
      // Private browsing can block storage; the session then lasts one page.
    }
  }

  function clearToken() {
    try {
      localStorage.removeItem(TOKEN_KEY);
    } catch (error) {
      // Nothing to do.
    }
  }

  /* ------------------------------------------------------------------
     3. SMALL ERROR CLASS + REQUEST HELPER
     ------------------------------------------------------------------ */

  function ApiError(message, status) {
    this.name = 'ApiError';
    this.message = message;
    this.status = status || 0;
  }

  ApiError.prototype = Object.create(Error.prototype);
  ApiError.prototype.constructor = ApiError;
  TB.ApiError = ApiError;

  /**
   * Turn FastAPI's error body into one readable sentence.
   *
   * FastAPI sends {"detail": "text"} for normal errors and
   * {"detail": [{"msg": "..."}]} for validation errors (HTTP 422).
   */
  function readableError(data) {
    if (!data) {
      return '';
    }

    var detail = data.detail;

    if (typeof detail === 'string') {
      return detail;
    }

    if (Object.prototype.toString.call(detail) === '[object Array]' && detail.length) {
      var first = detail[0];
      if (first && first.msg) {
        return first.msg;
      }
    }

    return '';
  }

  /**
   * One function for every HTTP call.
   *
   * @param {string} path    e.g. "/api/content"
   * @param {object} options { method, body, auth }
   * @returns {Promise}      resolves with the parsed JSON
   */
  function request(path, options) {
    options = options || {};

    var headers = { Accept: 'application/json' };

    if (options.body !== undefined) {
      headers['Content-Type'] = 'application/json';
    }

    // auth !== false means "attach the token when we have one".
    var token = readToken();
    if (options.auth !== false && token) {
      headers.Authorization = 'Bearer ' + token;
    }

    var settings = {
      method: options.method || 'GET',
      headers: headers
    };

    if (options.body !== undefined) {
      settings.body = JSON.stringify(options.body);
    }

    return fetch(API_BASE + path, settings).then(
      function (response) {
        var contentType = response.headers.get('content-type') || '';
        var isJson = contentType.indexOf('application/json') > -1;

        var bodyPromise = isJson
          ? response.json()
          : response.text().then(function (text) {
              return { detail: text };
            });

        return bodyPromise
          .catch(function () {
            return {};
          })
          .then(function (data) {
            if (!response.ok) {
              throw new ApiError(
                readableError(data) || 'Request failed with status ' + response.status,
                response.status
              );
            }
            return data;
          });
      },
      function () {
        // The second function handles a network failure (server not running).
        throw new ApiError(
          'Cannot reach the backend at ' + (API_BASE || window.location.origin) +
            '. Is the Python server running?',
          0
        );
      }
    );
  }

  TB.apiRequest = request;

  /* ------------------------------------------------------------------
     4. PUBLIC CONTENT
     ------------------------------------------------------------------
     GET /api/content returns the same object shape as the old js/data.js.
     Replacing window.TB_DATA means no rendering code had to change.
     ------------------------------------------------------------------ */

  function loadContent() {
    return request('/api/content', { auth: false })
      .then(function (content) {
        window.TB_DATA = content;
        return content;
      })
      .catch(function (error) {
        // Offline fallback: js/data.js already filled window.TB_DATA.
        console.warn(
          '[ThesisBridge] Using the bundled data.js because the API is unavailable:',
          error.message
        );
        return window.TB_DATA;
      });
  }

  /* ------------------------------------------------------------------
     5. SYNCING USER STATE TO SUPABASE
     ------------------------------------------------------------------
     The rest of the frontend calls TB.state.set('tb_bookmarks', [...]) etc.
     We keep that API, write to localStorage first (instant UI), then send
     the whole list to the backend in the background.
     ------------------------------------------------------------------ */

  var suppressSync = false; // true while we load data FROM the server

  var baseGet = TB.state.get.bind(TB.state);
  var baseSet = TB.state.set.bind(TB.state);

  // localStorage key -> API endpoint + JSON field name
  var LIST_ENDPOINTS = {
    tb_bookmarks: { url: '/api/me/bookmarks/ideas', field: 'ideaIds' },
    tb_savedSupervisors: { url: '/api/me/bookmarks/supervisors', field: 'supervisorIds' },
    tb_roadmap: { url: '/api/me/roadmap', field: 'stepIds' },
    tb_readGuides: { url: '/api/me/read-guides', field: 'guideIds' },
    tb_checklist: { url: '/api/me/checklist', field: 'itemIds' }
  };

  /**
   * Send a connection request / withdraw it.
   *
   * The frontend stores requests as an array in tb_connectRequests.
   * We compare the old and the new array and send only the difference:
   *   - supervisor id present now but not before -> POST
   *   - supervisor id present before but not now -> DELETE
   */
  function syncConnectionRequests(previous, next) {
    var before = {};
    var after = {};

    (previous || []).forEach(function (item) {
      before[item.supId] = true;
    });

    (next || []).forEach(function (item) {
      after[item.supId] = true;
    });

    (next || []).forEach(function (item) {
      if (before[item.supId]) {
        return; // already on the server
      }

      request('/api/connection-requests', {
        method: 'POST',
        body: {
          supervisorId: item.supId,
          name: item.name,
          email: item.email,
          topic: item.topic,
          message: item.message
        }
      }).catch(function (error) {
        console.warn('[ThesisBridge] Connection request was not saved:', error.message);
      });
    });

    Object.keys(before).forEach(function (supervisorId) {
      if (after[supervisorId]) {
        return; // still requested
      }

      if (!readToken()) {
        return; // guest: the request only existed in localStorage
      }

      request('/api/me/connection-requests/' + supervisorId, {
        method: 'DELETE'
      }).catch(function (error) {
        console.warn('[ThesisBridge] Could not withdraw the request:', error.message);
      });
    });
  }

  // Replace the localStorage-only writer with a localStorage + API writer.
  TB.state.set = function (key, value) {
    var previous = baseGet(key, null);

    // 1. Always update the local copy first so the UI reacts immediately.
    baseSet(key, value);

    // 2. Do not echo server data back to the server while hydrating.
    if (suppressSync) {
      return;
    }

    // 3. Connection requests are public, so they sync even for guests.
    if (key === 'tb_connectRequests') {
      syncConnectionRequests(previous || [], value || []);
      return;
    }

    // 4. Everything else needs a logged-in user.
    if (!readToken()) {
      return;
    }

    var endpoint = LIST_ENDPOINTS[key];

    if (!endpoint) {
      return;
    }

    var body = {};
    body[endpoint.field] = value || [];

    request(endpoint.url, { method: 'PUT', body: body }).catch(function (error) {
      console.warn('[ThesisBridge] Could not save ' + key + ':', error.message);
    });
  };

  /* ------------------------------------------------------------------
     6. LOADING THE USER'S STATE AFTER LOGIN / PAGE REFRESH
     ------------------------------------------------------------------ */

  function hydrate() {
    return request('/api/me/state').then(function (state) {
      suppressSync = true;

      try {
        // tb_user drives the navbar ("Hi, name") and the profile modal.
        TB.state.set('tb_user', state.user);

        TB.state.set('tb_bookmarks', state.bookmarkIdeaIds || []);
        TB.state.set('tb_savedSupervisors', state.savedSupervisorIds || []);
        TB.state.set('tb_roadmap', state.roadmapStepIds || []);
        TB.state.set('tb_readGuides', state.readGuideIds || []);
        TB.state.set('tb_checklist', state.checklistItemIds || []);

        // Convert the API shape { supervisorId, date } into the shape the
        // supervisors.js module already understands: { supId, date }.
        TB.state.set(
          'tb_connectRequests',
          (state.connectionRequests || []).map(function (item) {
            return {
              supId: item.supervisorId,
              name: item.name,
              email: item.email,
              topic: item.topic,
              message: item.message,
              date: item.date
            };
          })
        );
      } finally {
        // Always switch syncing back on, even if one line above throws.
        suppressSync = false;
      }

      return state.user;
    });
  }

  /* ------------------------------------------------------------------
     7. AUTHENTICATION HELPERS USED BY main.js
     ------------------------------------------------------------------ */

  TB.auth = {
    isLoggedIn: function () {
      return !!readToken();
    },

    /**
     * Log in, store the token, then download the user's saved lists.
     * Returns a Promise with the user object.
     */
    login: function (email, password) {
      return request('/api/auth/login', {
        method: 'POST',
        auth: false,
        body: { email: email, password: password }
      }).then(function (data) {
        writeToken(data.accessToken);
        TB.state.set('tb_user', data.user); // update the navbar immediately

        return hydrate()
          .catch(function () {
            return data.user; // the login worked; the lists can wait
          });
      });
    },

    /**
     * Create an account. The payload already uses the API's camelCase names:
     * { name, email, password, university, department, studentId, interest }
     */
    signup: function (payload) {
      return request('/api/auth/signup', {
        method: 'POST',
        auth: false,
        body: payload
      }).then(function (data) {
        writeToken(data.accessToken);
        TB.state.set('tb_user', data.user);

        return hydrate()
          .catch(function () {
            return data.user;
          });
      });
    },

    /**
     * Log out: forget the token and empty the local lists so the next visitor
     * on this computer cannot read the previous user's saved ideas.
     */
    logout: function () {
      clearToken();
      suppressSync = true;

      try {
        TB.state.set('tb_user', null);
        TB.state.set('tb_bookmarks', []);
        TB.state.set('tb_savedSupervisors', []);
        TB.state.set('tb_roadmap', []);
        TB.state.set('tb_readGuides', []);
        TB.state.set('tb_checklist', []);
        TB.state.set('tb_connectRequests', []);
      } finally {
        suppressSync = false;
      }
    }
  };

  /* ------------------------------------------------------------------
     8. TB.ready - the promise every module waits for
     ------------------------------------------------------------------
     Feature modules call:  TB.ready.then(boot)
     That guarantees the database content is already in window.TB_DATA and a
     returning user's bookmarks are already loaded, so nothing "jumps" after
     the first paint.
     ------------------------------------------------------------------ */

  TB.ready = loadContent().then(function () {
    if (!readToken()) {
      return null; // guest: nothing else to load
    }

    return hydrate().catch(function (error) {
      // A stale token must not break the page; behave like a guest instead.
      if (error.status === 401) {
        clearToken();
        TB.state.set('tb_user', null);
      }
      return null;
    });
  });

  // Expose the internals for debugging in the browser console.
  TB.api = {
    request: request,
    loadContent: loadContent,
    hydrate: hydrate
  };
})(window.TB);

Bug 1 — the FAQ page broke the whole content callবাগ ১ — FAQ পেজ পুরো কনটেন্ট কল ভেঙে দিয়েছিল

Detailবিস্তারিত
Symptomউপসর্গGET /api/content returned 500 Internal Server Error, so every page fell back to the bundled data.GET /api/content ৫০০ Internal Server Error দিত, তাই প্রতিটি পেজ বান্ডল করা ডেটায় ফিরে যেত।

class Faq(CamelModel):
    """
    The browser renders `q` and `a`, but the PostgreSQL columns are
    `question` and `answer`. validation_alias lets Pydantic *read* the
    database row while the JSON we send back still uses `q` / `a`.

    a: str = Field(validation_alias=AliasChoices("answer", "a"))

Bug 2 — a database error looked like a crashবাগ ২ — ডেটাবেস এরর ক্র্যাশের মতো দেখাচ্ছিল

Before the tables existed, a query raised postgrest.exceptions.APIError. FastAPI had no handler for it, so the browser received a bare Internal Server Error with no explanation — the worst kind of error message.

টেবিল তৈরি হওয়ার আগে কোয়েরি postgrest.exceptions.APIError ছুড়ত। FastAPI-তে তার হ্যান্ডলার ছিল না, তাই ব্রাউজার কোনো ব্যাখ্যা ছাড়া শুধু Internal Server Error পেত — সবচেয়ে খারাপ ধরনের এরর বার্তা।

The handler added in app/main.pyapp/main.py-তে যোগ করা হ্যান্ডলার

@app.exception_handler(APIError)
async def database_error_handler(request: Request, exc: APIError) -> JSONResponse:
    code = exc.code or ""
    message = exc.message or "Unknown database error."

    if code == "PGRST205":
        detail = ("The database tables do not exist yet. Open the Supabase dashboard, "
                  "go to SQL Editor, and run the file sql/001_create_tables.sql ...")
    elif code == "42501":
        detail = ("The database refused this query for permission reasons. Check that "
                  "SUPABASE_SERVICE_ROLE_KEY holds the secret key, not the publishable one.")
    else:
        detail = f"Database error ({code or 'unknown'}): {message}"

    return JSONResponse(status_code=503, content={"detail": detail})
  • 503, not 500: the service is temporarily unable to do its job, which is exactly what 503 means.৫০৩, ৫০০ নয়: সার্ভিস সাময়িকভাবে কাজ করতে পারছে না — ৫০৩-এর অর্থ ঠিক তাই।
  • Read the attributes: APIError exposes .code, .message, .hint, .details. Its args[0] is only a string and cannot be parsed reliably.অ্যাট্রিবিউট পড়া: APIError-তে .code, .message, .hint, .details আছে। এর args[0] শুধু স্ট্রিং, নির্ভরযোগ্যভাবে পার্স করা যায় না।
  • The frontend benefits for free: api.js already displays detail, so the student sees the instruction instead of a blank failure.ফ্রন্টএন্ড বিনা পরিশ্রমে উপকৃত: api.js আগেই detail দেখায়, তাই শিক্ষার্থী ফাঁকা ব্যর্থতার বদলে করণীয় দেখে।

Architecture and choicesআর্কিটেকচার ও সিদ্ধান্ত

Why FastAPI instead of Flask or Django?Flask বা Django-র বদলে FastAPI কেন?
Three reasons. It is async, so a request waiting on Supabase does not block the others. It validates every request with Pydantic automatically, so bad JSON is rejected before my code runs. And it generates the /docs page from the code, which gave me a testable API on day one. Django would have brought an admin panel and an ORM I did not need for 26 endpoints.তিনটি কারণ। এটি async, তাই Supabase-এর জন্য অপেক্ষারত একটি রিকোয়েস্ট বাকিগুলো আটকায় না। এটি Pydantic দিয়ে প্রতিটি রিকোয়েস্ট স্বয়ংক্রিয়ভাবে যাচাই করে, তাই আমার কোড চলার আগেই ভুল JSON বাতিল হয়। আর এটি কোড থেকে /docs পেজ বানায়, যা প্রথম দিনেই পরীক্ষণযোগ্য API দিয়েছে। Django একটি admin panel ও ORM আনত, যা ২৬টি endpoint-এর জন্য দরকার ছিল না।
Why is the API a separate application instead of PHP inside the HTML?HTML-এর ভিতরে PHP না করে API আলাদা অ্যাপ্লিকেশন কেন?
Because the secret database key must never reach the browser. With a server-side API the key lives in an environment variable and the browser only ever holds a short-lived user token. Separation also means the six static pages did not have to be rewritten — only api.js was added.কারণ সিক্রেট ডেটাবেস কী কখনো ব্রাউজারে পৌঁছানো যাবে না। সার্ভার-সাইড API-তে কী থাকে environment variable-এ, আর ব্রাউজার শুধু স্বল্পমেয়াদি ইউজার টোকেন ধরে। আলাদা রাখায় ছয়টি স্ট্যাটিক পেজ নতুন করে লিখতে হয়নি — শুধু api.js যোগ হয়েছে।
Why two Supabase clients?দুটি Supabase ক্লায়েন্ট কেন?
They have different permissions. Auth endpoints are designed for the publishable key, so signing in uses that. Table reads and writes need to bypass Row Level Security, which only the secret key can do — so those use the second client, and it never leaves the server.দুটির অনুমতি আলাদা। Auth endpoint publishable কী-এর জন্য তৈরি, তাই সাইন-ইন সেটি ব্যবহার করে। টেবিল পড়া-লেখায় Row Level Security বাইপাস দরকার, যা শুধু secret কী পারে — তাই সেগুলো দ্বিতীয় ক্লায়েন্ট ব্যবহার করে, আর এটি কখনো সার্ভার ছাড়ে না।
Why not query Supabase directly from JavaScript?JavaScript থেকে সরাসরি Supabase-এ কোয়েরি কেন নয়?
You can, and for a read-only site it would be shorter. But then all business rules — the sign-up transaction, the list replacement, the guest-versus-member rule — would either live in the browser, where they can be edited, or in RLS policies, which are harder to explain. And the secret key could not be used at all.করা যায়, আর শুধু পড়ার সাইটে তা ছোট হতো। কিন্তু তখন সব ব্যবসায়িক নিয়ম — সাইন-আপ লেনদেন, লিস্ট রিপ্লেস, গেস্ট-বনাম-মেম্বার নিয়ম — হয় ব্রাউজারে থাকত, যেখানে সম্পাদনা করা যায়, নয়তো RLS পলিসিতে, যা ব্যাখ্যা করা কঠিন। আর secret কী ব্যবহারই করা যেত না।
Why is public/ a separate folder from app/?app/ থেকে public/ আলাদা ফোল্ডার কেন?
It is a security boundary made visible in the file tree. Everything in public/ is downloadable by anyone; nothing in app/ is. Keeping the two apart means a Python file can never be served by accident.এটি ফাইল-গাছে দৃশ্যমান একটি নিরাপত্তা-সীমানা। public/-এর সবকিছু যে কেউ নামাতে পারে; app/-এর কিছুই নয়। আলাদা রাখায় কোনো Python ফাইল ভুলে সার্ভ হওয়ার সুযোগ নেই।

Database and data modellingডেটাবেস ও ডেটা মডেলিং

What is Row Level Security and why does it matter if your API uses the secret key?Row Level Security কী, আর আপনার API secret কী ব্যবহার করলে এটি কেন দরকার?
RLS makes PostgreSQL filter rows per user by policy. My API bypasses it by design, so its value is defence in depth: if the publishable key leaks — and that key is in every browser by nature — an attacker calling Supabase directly still cannot read another student's bookmarks. The policies are the second lock.RLS পলিসি অনুযায়ী PostgreSQL-কে প্রতি ইউজারে রো ফিল্টার করায়। আমার API ইচ্ছাকৃতভাবে এটি বাইপাস করে, তাই এর মূল্য defence in depth: publishable কী ফাঁস হলে — আর সেই কী স্বভাবতই প্রতিটি ব্রাউজারে থাকে — সরাসরি Supabase-কে কল করা আক্রমণকারী তবুও অন্য শিক্ষার্থীর বুকমার্ক পড়তে পারে না। পলিসিগুলো দ্বিতীয় তালা।
Why a separate profiles table instead of adding columns to the auth table?auth টেবিলে কলাম যোগ না করে আলাদা profiles টেবিল কেন?
auth.users belongs to Supabase and holds credentials. Application fields such as university and department are mine, so they live in public.profiles with the same uuid as the primary key — a one-to-one relationship. Upgrading Supabase then cannot overwrite my data.auth.users Supabase-এর, সেখানে ক্রেডেনশিয়াল থাকে। বিশ্ববিদ্যালয় ও ডিপার্টমেন্টের মতো অ্যাপ্লিকেশন ফিল্ড আমার, তাই সেগুলো public.profiles-এ, একই uuid প্রাইমারি কীসহ — এক-থেকে-এক সম্পর্ক। তখন Supabase আপগ্রেড আমার ডেটা মুছে দিতে পারে না।
Why do the bookmark tables have no foreign key to research_ideas?বুকমার্ক টেবিলে research_ideas-এর foreign key নেই কেন?
A deliberate trade-off for the migration. The integer ids were reused from the old data.js so bookmarks saved before the backend existed still resolve to the right idea. The API validates the id on write and returns 400 for an unknown one, which covers the same ground without a hard constraint.মাইগ্রেশনের জন্য ইচ্ছাকৃত সমঝোতা। পূর্ণসংখ্যা id পুরোনো data.js থেকে পুনর্ব্যবহৃত, যাতে ব্যাকএন্ডের আগে সেভ করা বুকমার্কও সঠিক আইডিয়ায় মেলে। API লেখার সময় id যাচাই করে আর অজানা id-তে ৪০০ দেয়, যা কঠোর constrain ছাড়াই একই কাজ করে।
Why is unique (user_id, idea_id) important?কেন unique (user_id, idea_id) গুরুত্বপূর্ণ?
It is what makes upsert possible: PostgreSQL needs a unique constraint to know which row to update instead of inserting a duplicate. It also makes a double-click harmless — the second insert becomes a no-op.এটাই upsert সম্ভব করে: কোন রো আপডেট করতে হবে তা জানতে PostgreSQL-এর unique constraint দরকার, নইলে ডুপ্লিকেট ইনসার্ট হয়। এটি দুইবার ক্লিককেও নিরীহ করে — দ্বিতীয় ইনসার্ট কিছুই করে না।
What is an index and where did you use one?ইনডেক্স কী, আর কোথায় ব্যবহার করেছেন?
An index is a lookup structure that lets PostgreSQL find rows without scanning the table. Every user table is indexed on user_id, because every query filters by it, and content tables are indexed on the columns used for sorting and filtering.ইনডেক্স হলো একটি খোঁজার গঠন, যা PostgreSQL-কে টেবিল স্ক্যান না করে রো খুঁজতে দেয়। প্রতিটি user টেবিল user_id-তে ইনডেক্সড, কারণ প্রতিটি কোয়েরি তা দিয়ে ফিল্টার করে, আর কনটেন্ট টেবিল সাজানো ও ফিল্টারে ব্যবহৃত কলামে ইনডেক্সড।
Why no ORM such as SQLAlchemy?SQLAlchemy-র মতো ORM কেন নয়?
The Supabase client already speaks PostgREST, so a second abstraction layer would add code without removing any. Every query in this project is short and readable as it is, and there are no complex joins to manage.Supabase ক্লায়েন্ট আগেই PostgREST-এর সাথে কথা বলে, তাই দ্বিতীয় abstraction স্তর কোড বাড়াত কিন্তু কিছু কমাত না। এখানে প্রতিটি কোয়েরি ছোট ও পাঠযোগ্য, আর সামলানোর মতো জটিল join নেই।

Securityনিরাপত্তা

How are passwords stored?পাসওয়ার্ড কীভাবে সংরক্ষিত হয়?
They are never stored by my code. They go to Supabase Auth, which hashes them with bcrypt inside its own schema. My database has no password column, so a dump of my tables contains no credential at all.আমার কোড সেগুলো কখনো সংরক্ষণ করে না। সেগুলো Supabase Auth-এ যায়, যা নিজের স্কিমায় bcrypt দিয়ে হ্যাশ করে। আমার ডেটাবেসে পাসওয়ার্ড কলামই নেই, তাই আমার টেবিলের ডাম্পে কোনো ক্রেডেনশিয়ালই থাকে না।
What is the difference between authentication and authorisation here?এখানে authentication ও authorisation-এর পার্থক্য কী?
Authentication is proving who you are — login, and the token on each request. Authorisation is what you may touch — every query is filtered by .eq("user_id", current_user["id"]), so even a valid token cannot read another user's rows.Authentication হলো আপনি কে তা প্রমাণ করা — লগইন, আর প্রতিটি রিকোয়েস্টে টোকেন। Authorisation হলো আপনি কী স্পর্শ করতে পারেন — প্রতিটি কোয়েরি .eq("user_id", current_user["id"]) দিয়ে ফিল্টার করা, তাই বৈধ টোকেনও অন্যের রো পড়তে পারে না।
Why does a wrong password and an unknown email give the same message?ভুল পাসওয়ার্ড ও অজানা ইমেইল একই বার্তা কেন দেয়?
To prevent account enumeration. Different messages would turn the login form into a tool for discovering which students have accounts. The test suite asserts that the two responses are byte-identical.অ্যাকাউন্ট enumeration আটকাতে। আলাদা বার্তা লগইন ফর্মকে এমন হাতিয়ার বানাত যা দিয়ে জানা যেত কোন শিক্ষার্থীর অ্যাকাউন্ট আছে। টেস্ট স্যুট নিশ্চিত করে দুটি উত্তর হুবহু এক।
Is the search box safe from SQL injection?সার্চ বক্স কি SQL injection থেকে নিরাপদ?
Yes, for two reasons. Values are sent to PostgREST as parameters, not concatenated into SQL, so quoting cannot break out. On top of that, _safe_search strips comma, parenthesis and asterisk, because those characters are PostgREST filter syntax rather than SQL.হ্যাঁ, দুই কারণে। মানগুলো PostgREST-এ প্যারামিটার হিসেবে যায়, SQL-এ জোড়া লাগে না, তাই কোট দিয়ে বেরোনো যায় না। তার উপর _safe_search কমা, বন্ধনী ও অ্যাস্টেরিস্ক সরায়, কারণ সেগুলো SQL নয়, PostgREST ফিল্টার সিনট্যাক্স।
Where could stored XSS come from, and what did you do about it?Stored XSS কোথা থেকে আসতে পারত, আর আপনি কী করেছেন?
A student's name is stored in the database and rendered into HTML. Every such value passes through TB.esc() before it enters the page, including the prefilled form attributes. Trusting stored data is exactly how stored XSS happens.শিক্ষার্থীর নাম ডেটাবেসে থাকে এবং HTML-এ রেন্ডার হয়। এমন প্রতিটি মান পেজে ঢোকার আগে TB.esc()-এর মধ্য দিয়ে যায়, প্রি-ফিল করা ফর্ম অ্যাট্রিবিউটসহ। সংরক্ষিত ডেটাকে বিশ্বাস করাই stored XSS-এর কারণ।
Is there rate limiting?rate limiting আছে কি?
No, and that is a real gap. A public sign-up endpoint without a limit can be abused. The fix is a small counter in PostgreSQL or Vercel's firewall rules; it is listed as future work rather than pretended to exist.না, এবং এটি সত্যিকারের ঘাটতি। সীমা ছাড়া পাবলিক সাইন-আপ endpoint-এর অপব্যবহার সম্ভব। সমাধান PostgreSQL-এ ছোট কাউন্টার বা Vercel-এর firewall নিয়ম; এটি থাকার ভান না করে ভবিষ্যৎ কাজ হিসেবে লেখা আছে।

API designAPI ডিজাইন

Why send the whole list instead of adding one bookmark at a time?একবারে একটি বুকমার্ক যোগ না করে পুরো লিস্ট কেন পাঠানো?
Because add and remove are two different calls that can arrive out of order, and then the browser and the database disagree. Sending the whole array makes the operation idempotent: the same request twice leaves the same rows.কারণ যোগ ও বাদ দেওয়া দুটি আলাদা কল, যা উল্টো ক্রমে পৌঁছাতে পারে, তখন ব্রাউজার ও ডেটাবেস একমত থাকে না। পুরো অ্যারে পাঠালে কাজটি idempotent হয়: একই রিকোয়েস্ট দুইবার পাঠালেও একই রো থাকে।
What does idempotent mean, and why does PUT fit?idempotent মানে কী, আর PUT কেন মানানসই?
Idempotent means repeating the request produces the same final state. PUT means "make this resource look like this", which is exactly the replace-the-list semantics. POST would imply "add another one", which is not what the button does.Idempotent মানে রিকোয়েস্ট পুনরাবৃত্তি করলে চূড়ান্ত অবস্থা একই থাকে। PUT মানে "এই রিসোর্সকে এমন করো", যা হুবহু লিস্ট-রিপ্লেস অর্থ। POST বোঝাত "আরেকটি যোগ করো", যা বোতামটি করে না।
Why does the API use camelCase when PostgreSQL uses snake_case?PostgreSQL snake_case ব্যবহার করলে API camelCase কেন?
The database follows SQL convention and the JavaScript follows its own. Instead of rewriting the six pages, CamelModel converts on the way out, and populate_by_name lets the same model read database rows. One class serves both sides.ডেটাবেস SQL রীতি মানে আর JavaScript নিজের রীতি। ছয়টি পেজ নতুন করে লেখার বদলে CamelModel বেরোনোর পথে রূপান্তর করে, আর populate_by_name একই মডেলকে ডেটাবেস রো পড়তে দেয়। একটি ক্লাসই দুই পক্ষের কাজ করে।
Why 503 for a database error instead of 500?ডেটাবেস এররে ৫০০-এর বদলে ৫০৩ কেন?
500 means the code itself is broken. 503 means the service is temporarily unable to do its job, which is what a missing table or a refused permission is. The distinction tells the reader whether to fix the code or the configuration.৫০০ মানে কোড নিজেই ভাঙা। ৫০৩ মানে সার্ভিস সাময়িকভাবে কাজ করতে পারছে না, আর অনুপস্থিত টেবিল বা প্রত্যাখ্যাত অনুমতি ঠিক তাই। এই পার্থক্য পাঠককে বলে কোড না কনফিগারেশন ঠিক করতে হবে।
What is a dependency in FastAPI?FastAPI-তে dependency কী?
A function FastAPI runs before the route and injects the result into it. get_current_user reads the header, verifies the token and returns the user — so no route repeats that code, and a route that declares it cannot accidentally run unauthenticated.এমন ফাংশন যা FastAPI রুটের আগে চালায় এবং ফলাফল রুটে ইনজেক্ট করে। get_current_user হেডার পড়ে, টোকেন যাচাই করে ইউজার ফেরত দেয় — তাই কোনো রুট সেই কোড পুনরাবৃত্তি করে না, আর যে রুট এটি ঘোষণা করে সে ভুলে অনুমতিহীন চলতেও পারে না।
Why AliasChoices on the FAQ model?FAQ মডেলে AliasChoices কেন?
The database columns are question and answer, but the frontend has always rendered q and a. Aliases let Pydantic read either name while still emitting the shorter one, so a schema change needed zero frontend edits. That was a real bug I hit.ডেটাবেস কলাম question ও answer, কিন্তু ফ্রন্টএন্ড সবসময় q ও a রেন্ডার করত। alias Pydantic-কে যেকোনো নাম পড়তে দেয় আর ছোটটিই দেয়, তাই স্কিমা বদলে ফ্রন্টএন্ডে শূন্য এডিট লাগে। এটি আমার ধরা পড়া আসল বাগ।

Deployment and productionডিপ্লয় ও প্রোডাকশন

What is a serverless function, and what is a cold start?serverless function কী, আর cold start কী?
A function that runs in a container Vercel starts only when a request arrives and stops when it is idle. A cold start is the first request after that idle period, which has to boot Python, import FastAPI and build the Supabase client — about a second here.এমন ফাংশন যা Vercel-এর কনটেইনারে চলে, রিকোয়েস্ট এলে চালু হয় আর নিষ্ক্রিয় হলে বন্ধ হয়। cold start হলো সেই নিষ্ক্রিয়তার পর প্রথম রিকোয়েস্ট, যাকে Python চালু করতে, FastAPI আমদানি করতে ও Supabase ক্লায়েন্ট বানাতে হয় — এখানে প্রায় এক সেকেন্ড।
Why is there no CORS problem in production but one locally?প্রোডাকশনে CORS সমস্যা নেই কিন্তু লোকালে কেন?
In production the pages and the API share one origin, so the browser never makes a cross-origin request. Locally the page is on port 8417 and the API on 8000, which is cross-origin, so CORS_ORIGINS has to allow the page's address.প্রোডাকশনে পেজ ও API একই origin-এ, তাই ব্রাউজার কখনো cross-origin রিকোয়েস্ট করে না। লোকালে পেজ ৮৪১৭ পোর্টে আর API ৮০০০-এ, যা cross-origin, তাই CORS_ORIGINS-কে পেজের ঠিকানা অনুমোদন করতে হয়।
How do you prove the site is reading PostgreSQL and not the bundled file?সাইটটি বান্ডল করা ফাইলের বদলে PostgreSQL পড়ছে কীভাবে প্রমাণ করবেন?
Three ways. Delete a row in the Table Editor and reload — the card disappears. Clear localStorage, reload, and the bookmarks come back from GET /api/me/state. Or watch the Network tab and see the /api/content response carrying the rows.তিন উপায়। Table Editor-এ একটি রো মুছে রিলোড করুন — কার্ডটি চলে যায়। localStorage মুছে রিলোড করুন, বুকমার্ক GET /api/me/state থেকে ফিরে আসে। অথবা Network ট্যাব দেখুন, /api/content উত্তর রো বহন করছে।
What happens if Vercel and Supabase are in different regions?Vercel ও Supabase আলাদা রিজিয়নে থাকলে কী হয়?
Every query pays the round-trip twice — function to database and back — so latency adds up. The fix is to create the Supabase project in the region closest to the function; this project keeps both as close as the free plan allows.প্রতিটি কোয়েরি রাউন্ড-ট্রিপ দুইবার দেয় — ফাংশন থেকে ডেটাবেস ও ফিরে — তাই লেটেন্সি যোগ হয়। সমাধান হলো ফাংশনের নিকটতম রিজিয়নে Supabase প্রজেক্ট বানানো; এই প্রজেক্টে ফ্রি প্ল্যান যতটা দেয়, দুটোই কাছাকাছি রাখা হয়েছে।
What would you change for 10,000 users?১০,০০০ ইউজারের জন্য কী বদলাতেন?
Five things. Use a connection pooler because serverless functions open many short connections. Add composite indexes matching the real filters. Cache content reads, which change rarely. Add rate limiting on sign-up and search. And move the list writes to a queue if they ever became heavy. The API shapes would not change.পাঁচটি জিনিস। connection pooler ব্যবহার করতাম, কারণ serverless ফাংশন অনেক ছোট সংযোগ খোলে। বাস্তব ফিল্টারের সাথে মেলা composite index যোগ করতাম। কম বদলানো কনটেন্ট পড়া ক্যাশ করতাম। সাইন-আপ ও সার্চে rate limiting যোগ করতাম। আর লিস্ট-লেখা ভারী হলে queue-তে সরাতাম। API-এর আকার বদলাত না।
How would you add email notification when a request arrives?রিকোয়েস্ট এলে ইমেইল নোটিফিকেশন কীভাবে যোগ করবেন?
The row is already stored, so the insert is the event. Add a call after a successful insert to an email provider's API, inside a try block so a mail failure never loses the request. A background task or a Supabase database webhook would be the cleaner version at scale.রো আগেই সংরক্ষিত হয়, তাই insert-ই ঘটনা। সফল insert-এর পরে ইমেইল প্রোভাইডারের API-তে একটি কল যোগ করতাম, try ব্লকে, যাতে মেইল ব্যর্থ হলেও রিকোয়েস্ট না হারায়। বড় পরিসরে background task বা Supabase database webhook আরও পরিচ্ছন্ন।

Testing and honest limitationsপরীক্ষা ও সৎ সীমাবদ্ধতা

How was this tested?এটি কীভাবে পরীক্ষা করা হয়েছে?
In two layers. A 57-assertion HTTP suite ran against the real Supabase project and checked status codes, field names, the five lists, both request paths and the login round trip. Then a real browser run used the actual forms, including deleting local storage to prove the server restore. Zero failures at the end.দুই স্তরে। ৫৭টি assertion-এর HTTP স্যুট আসল Supabase প্রজেক্টের বিরুদ্ধে চলে স্টেটাস কোড, ফিল্ড-নাম, পাঁচটি লিস্ট, দুই রিকোয়েস্ট পথ ও লগইন রাউন্ড ট্রিপ যাচাই করেছে। তারপর আসল ব্রাউজার রানে আসল ফর্ম ব্যবহার হয়েছে, লোকাল স্টোরেজ মুছে সার্ভার-রিস্টোর প্রমাণসহ। শেষে শূন্য ব্যর্থতা।
What is the biggest weakness of this system?এই সিস্টেমের সবচেয়ে বড় দুর্বলতা কী?
The token has no refresh flow, so a session ends after one hour and the user must log in again. It is a deliberate scope decision, not an oversight, and the honest fix is to store the refresh token and call Supabase's refresh endpoint before expiry.টোকেনে রিফ্রেশ ফ্লো নেই, তাই এক ঘণ্টা পর সেশন শেষ হয় আর ইউজারকে আবার লগইন করতে হয়। এটি ইচ্ছাকৃত পরিসীমা-সিদ্ধান্ত, অবহেলা নয়, আর সৎ সমাধান হলো রিফ্রেশ টোকেন রাখা এবং মেয়াদ শেষের আগে Supabase-এর refresh endpoint কল করা।
Two tabs change the same list. What happens?দুই ট্যাব একই লিস্ট বদলায়। কী হয়?
Last write wins. Each tab sends its whole list, so the later request replaces the earlier one. For one student on two devices that is acceptable; a version number per list would turn it into a conflict the UI could report.শেষ লেখাটি জেতে। প্রতিটি ট্যাব পুরো লিস্ট পাঠায়, তাই পরের রিকোয়েস্ট আগেরটি বদলে দেয়। দুই ডিভাইসে একজন শিক্ষার্থীর জন্য এটি গ্রহণযোগ্য; প্রতি লিস্টে একটি version নম্বর থাকলে এটি এমন সংঘাত হতো যা UI জানাতে পারত।
If you had one more week, what would you build first?আরেক সপ্তাহ পেলে প্রথমে কী বানাতেন?
Refresh tokens, then rate limiting, then password reset. Those three make the account system complete and safe. Email notification for requests and a small admin screen for supervisors would be next.রিফ্রেশ টোকেন, তারপর rate limiting, তারপর পাসওয়ার্ড রিসেট। এই তিনটি অ্যাকাউন্ট সিস্টেমকে পূর্ণ ও নিরাপদ করে। এরপর রিকোয়েস্টের ইমেইল নোটিফিকেশন ও সুপারভাইজারদের জন্য ছোট admin স্ক্রিন।

Adding a feature — the order that worksফিচার যোগ করা — যে ক্রমে কাজ করে

1. Database first     sql/002_add_column.sql   (and run it in the SQL Editor)
2. Seed / backfill    update the JSON and re-run the seeder if content changes
3. Schema             app/schemas.py          (add the field to the model)
4. Router             the endpoint that reads or writes it
5. Frontend           api.js helper, then the page module
